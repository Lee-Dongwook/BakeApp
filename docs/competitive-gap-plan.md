# BakeApp 경쟁 제품 갭 분석 및 실행 계획

작성일: 2026-09-01

## 1. 결론

BakeApp은 지금 **노코드 앱 빌더의 핵심 엔진을 검증하는 프로토타입** 단계다. 화면 AST 편집, 동적 PostgreSQL 스키마/CRUD, React·React Native 코드 생성, API 호출, 일부 워크플로우라는 출발점은 좋다.

하지만 FlutterFlow, Bubble, Base44와 같은 완성형 제품과 비교하면, 사용자가 만든 앱을 **저장하고, 인증을 붙이고, 데이터와 연결해, 안전하게 배포하는 제품 흐름**이 아직 이어지지 않는다. 따라서 다음 목표는 기능 수를 늘리는 것이 아니라 `프로젝트 → 제작 → 미리보기 → 배포` 흐름을 하나로 완성하는 것이다.

### 권장 포지셔닝

처음부터 세 제품 전체를 따라가지 않는다. BakeApp은 다음 문제에 집중한다.

> **Supabase/PostgreSQL 기반의 내부 업무 도구를, 한국어 UI에서 빠르게 설계·배포하는 앱 빌더**

이 포지셔닝은 이미 있는 동적 스키마, CRUD API, Swagger, RLS 기반 코드를 활용할 수 있고, FlutterFlow의 네이티브 앱 생태계나 Bubble의 긴 플러그인 생태계를 즉시 재현하지 않아도 된다.

## 4. 우선순위 갭

### P0 — 앱을 실제로 만들고 다시 열 수 있게 하기

1. **프로젝트 영속화**
   - 프로젝트, 페이지, 컴포넌트 AST, API 정의, 워크플로우를 DB에 저장한다.
   - `새 프로젝트`, `저장`, `불러오기`, 자동 저장, 변경됨 표시를 제공한다.
   - 이유: 저장되지 않는 빌더는 사용자의 실제 작업물이 될 수 없다.

2. **빌더 사용자 인증과 프로젝트 권한**
   - 기존 Supabase 인증 API를 프론트 로그인/세션과 연결한다.
   - 프로젝트 소유자와 멤버 권한을 분리하고, 현재 하드코딩된 `projectId`를 실제 프로젝트 ID로 바꾼다.
   - 이유: 동적 테이블과 RLS가 있어도 프로젝트 경계가 UI에서 보장되지 않는다.

3. **데이터 모델을 화면과 연결**
   - 테이블 목록/필드 편집, 레코드 미리보기, CRUD 액션 선택, 목록·상세 화면 바인딩을 제공한다.
   - 최소 컴포넌트: `Data Table/List`, `Image`, `Select`, `Checkbox`, `Form`.
   - 이유: 현재는 DB를 만들 수는 있지만, 그 데이터를 화면에 자연스럽게 보여 주는 경로가 없다.

### P1 — 내부 도구 한 개를 끝까지 만들 수 있게 하기

4. **워크플로우 편집기 완성**
   - 트리거: 클릭, 페이지 로드, 폼 제출.
   - 액션: Create/Read/Update/Delete, API 호출, 페이지 이동, 알림.
   - 제어: 조건 분기, 성공/실패 경로, 로딩/오류 상태, 액션 결과 변수.
   - 프론트와 백엔드의 액션 명칭 및 파라미터 스키마를 하나의 타입/계약으로 통일한다.
   - 이유: 현재 런타임이 지원하는 `NAVIGATE_TO`, `RUN_QUERY`가 속성 패널에서는 생성·설정되지 않아 기능이 단절되어 있다.

5. **실전 API 통합**
   - 환경별 base URL, 헤더/비밀값, query parameter, PATCH, 응답 JSON Path, API 그룹, 요청 테스트를 추가한다.
   - OpenAPI JSON/URL 가져오기로 API 정의를 생성한다.
   - 비밀값은 브라우저 AST에 저장하지 않고 서버의 암호화된 프로젝트 설정에 저장한다.
   - 이유: 경쟁 제품은 외부 API를 한 번 연결하고 여러 화면/액션에서 재사용한다.

6. **UI 제작성**
   - 컴포넌트 트리, 복제/이동, 되돌리기/다시 실행, 정렬/간격, 테마 토큰, 재사용 컴포넌트, 데스크톱·태블릿·모바일 브레이크포인트를 추가한다.
   - 캔버스는 기기별 프리뷰를 제공하고, 스타일 편집은 유효한 CSS 값만 허용한다.

### P2 — 배포 가능한 제품으로 만들기

7. **Publish 파이프라인**
   - Preview와 Published 버전을 분리한다.
   - 우선 웹 정적 배포부터 시작하고, 프로젝트별 URL·환경 변수·배포 이력·이전 버전 롤백을 제공한다.
   - React Native는 단순 코드 다운로드를 유지하되, 앱스토어 빌드는 P3로 미룬다.

8. **코드 생성 품질**
   - 생성 코드에 타입 검사와 스냅샷 테스트를 붙인다.
   - 현재 생성기는 이벤트/동적 바인딩/워크플로우를 완전하게 출력하지 않으므로, "실행 가능한 코드"와 "참고용 코드" 상태를 명확히 구분한다.
   - 내보내기는 페이지 하나가 아닌 프로젝트 구조, 환경 변수 예시, README를 포함한다.

9. **운영 품질**
   - 오류 추적, 요청 로그, 프로젝트 활동 로그, 사용량 제한, 백업/내보내기, 기본 접근성 검사, 성능 검사.

### P3 — 경쟁 우위를 위한 확장

10. **AI 앱 생성**
    - 자연어 요구사항 → 페이지/데이터 모델/API/워크플로우 초안을 제안한다.
    - 반드시 변경 전 diff·미리보기·승인 단계를 둔다.
    - Base44를 정면으로 따라가기보다, "한국어 업무 앱 요구사항을 구조화해 주는 AI"에 특화한다.

11. **협업과 생태계**
    - 멤버 초대, 역할, 변경 이력, 댓글, 버전 비교/복원.
    - 템플릿 갤러리와 검증된 커넥터를 제공한다.

12. **네이티브 모바일**
    - 기기 프리뷰, 푸시 알림, 카메라/위치, iOS·Android 빌드 및 스토어 제출을 지원한다.
    - 이 단계는 FlutterFlow의 주력 영역이므로, 실제 수요가 검증된 뒤 투자한다.

## 5. 권장 로드맵

| 단계                 | 기간 예시 | 완료 기준                                                                                        |
| -------------------- | --------- | ------------------------------------------------------------------------------------------------ |
| 1. Foundation        | 2–3주     | 로그인한 사용자가 프로젝트를 만들고, 페이지/AST/API/워크플로우를 저장 후 다시 열 수 있다.        |
| 2. Internal-tool MVP | 3–4주     | 테이블 하나를 만들고, 목록·등록 폼·수정·삭제 화면을 만든 뒤 권한 있는 사용자로 테스트할 수 있다. |
| 3. Publish beta      | 2–3주     | 웹 URL로 배포하고, Preview/Published 분리·환경 변수·배포 이력·롤백을 제공한다.                   |
| 4. AI assisted build | 2–3주     | 자연어 요구사항에서 CRUD 앱 초안을 만들고, 사용자가 diff를 보고 적용할 수 있다.                  |

## 6. 다음 구현 스프린트 제안

가장 먼저 아래 한 개의 사용자 시나리오를 완성한다.

> 관리자가 로그인 → `재고 관리` 프로젝트 생성 → `products` 테이블 생성 → 상품 목록/등록 화면 생성 → 폼 제출 시 DB 저장 → 웹 URL로 배포

이를 위해 필요한 작업 순서:

1. `Project` 데이터 모델과 AST 저장 API 설계
2. 프론트 로그인·프로젝트 대시보드·자동 저장
3. 테이블/필드 선택과 List/Form 데이터 바인딩
4. CRUD·이동·API 액션을 포함한 워크플로우 계약 통일
5. Preview/Published 웹 배포
6. 위 시나리오의 E2E 테스트와 사용 가이드 작성

## 7. 지금 하지 않을 것

- FlutterFlow 수준의 iOS/Android 스토어 빌드 자동화
- Bubble 수준의 대형 플러그인 마켓플레이스
- 실시간 공동 편집(CRDT)
- 범용 AI 에이전트/수십 개의 SaaS 커넥터

이 기능들은 제품의 핵심 흐름이 검증된 뒤에 추가한다. 지금은 **저장 가능한 프로젝트 한 개를 데이터와 워크플로우까지 연결해 웹에 배포하는 경험**이 가장 큰 가치다.
